## 1. 선행 — 실거시 데이터 도입

STAGE 6 계획서 §5 가 D축을 보류한 사유("거시 91개가 합성 난수")는 해소됐다.

|---|---|---|
| 거시 원천 | `default_rng(20260829)` 합성 프레임 | `api_data_processing` 실수집 178컬럼 |
| 기간 | — | 202101 ~ 202605 (65개월) |

기존 합성 패널과 `portal_v2.duckdb` 는 **건드리지 않았다**. 실거시 패널은
`--tag real` 로 별도 파일에 저장했다 (`step6` 에 `--tag` / `--lag` 옵션 신설).

### 코드 수정 2건 — `eda_pipeline/step6_macro_integration.py`

**(1) `MACRO_LAG_MONTHS` 1 → 0. 이중 시차 제거.**
공표 시차는 상류 `impute_data.py` Phase 1 이 지표군별로 이미 건다
(A 0개월 / B +1 / C +2). step6 가 전 컬럼에 일괄 `shift(1)` 을 더 걸어
실제로는 A=1 / B=2 / C=3 이었다.

**(2) 조인 후 `ffill().bfill()` 제거 → 예외로 전환.**
거시 결측이 남으면 결측 월 목록과 원천/패널 범위를 붙여 `ValueError` 를 던진다.
bfill 은 미래 값을 과거로 끌어오므로 결측을 메우는 순간 그 구간이 통째로 누수가
된다. `apply_macro_lag` 안의 `.bfill()` 도 같은 이유로 없앴다 — 구 구현은
shift 직후 첫 행을 자기 자신의 미시차 값으로 되메워 첫 달에 미래 참조가 남았다.

## 2. G1-5 — 1차 실패와 그 원인 (기록 보존)

1차 실행에서 구 기준(`8종 전부 BASE_YM 내 분산 > 0`)에 4종이 미달했다.

### 원인 A — 거시 충격이 그 달에 **정확히 0** 이다 (13개월)

`rate_shock_x_leverage` = `base_rate_diff12` × `exp_rate`.
`base_rate_diff12` 는 기준금리의 12개월 차분이다. 기준금리는 금통위 결정 시에만
바뀌는 계단 함수라, **12개월 전과 같은 수준이면 차분이 정확히 0** 이 된다.

| 구간 | 개월 | 사유 |
|---|---:|---|
| 202107 ~ 202109 | 3 | 기준금리 12개월 연속 동결 |
| 202403 ~ 202411 | 9 | 3.50% 장기 동결 |

`bsi_x_industry` 의 202412 도 같은 유형이다 (`BSI_mfg_biz_yoy` = 0).

그 달에도 노출도 `exp_rate` 에는 분산이 살아 있다 (std 0.216~0.229,
nonnull 16,132~18,543행). 곱해지는 충격이 0 일 뿐이다.

**이것은 시점 더미로의 퇴화와 정반대 현상이다.** 시점 더미란 "같은 달 모든
기업이 같은 0 아닌 값을 갖는 것"인데, 여기서는 모든 기업이 0 이다.
합성 난수는 정확히 0 을 만들지 못해 STAGE 5 는 이 항을 53/53 으로 통과시켰다.
**실데이터로 바꾼 뒤에야 드러난 것이므로, 발견 자체가 정상적인 검증 결과다.**

### 기준 개정 R1 — 문장을 의도에 맞췄다

G1-5 를 만들 때의 근거는 "분산이 0이면 시점 더미로 퇴화한 것"이었고 검증
대상은 "충격이 존재할 때 기업마다 다르게 반응하는가"였다. 그런데 쓴 문장이
"전 월에서 분산 > 0"이라 **충격 자체가 0인 달까지 실패로 잡는 기준**이 됐다.
의도와 문장의 불일치를 바로잡았다. 전문과 사유는 기준서 §개정 이력 R1 참조.

금리 상호작용항을 0 이 안 나오는 지표로 바꾸는 대안은 **채택하지 않았다.**
동결 구간의 0 은 데이터의 사실이지 결함이 아니며, 지표를 바꿔 0 을 없애는 것은
"기준을 통과시키기 위한 설계 변경"이 된다.
