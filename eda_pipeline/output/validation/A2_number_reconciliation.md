## 3. 양성 — 171건 차이

step5 `prepare()` 의 실행 순서를 산출물로 재현했다.

| 단계 | 행수 | 양성 |
|---|---:|---:|
| (a) `generate_12m_target` 직후 | 951,908 | **9,985** |
| (b) `drop_in_default_periods` 직후 | 948,214 (−3,694) | **9,814** (−171) |
| (c) `apply_censoring` 직후 | 948,214 (−0) | 9,814 (−0) |

- **171건 차이는 정확히 `drop_in_default_periods` 적용 전/후다.** 재현 오차 0.
- 우측절단(`apply_censoring`)은 이 패널에서 **0행**을 지운다.
  `CENSOR_END='202605'`, `HORIZON_MONTHS=12`, 패널 최대월 202505 → 202505+12 = 202605 ≤ 202605.
  즉 절단은 이미 step2 스파인 단계에서 충족되어 있었다.
- 사라진 양성 171행 = **55사**, 202109~202505. 부도 진행 중(부도월~정상화월) 이면서
  그 구간 안에서 12개월 내 **다음 부도**가 또 잡히는 행이다. 다중부도 기업의
  부도 진행 구간이므로 학습에서 빠지는 것이 맞다.

### 설정 상수 확인 (`eda_pipeline/step5_panel_prep.py`)

| 상수 | 값 | 의미 |
|---|---|---|
| `EXCLUDE_DEFAULT_MONTH` | `True` | 부도 발생 월 자체를 제거. 제거 구간 = `[부도월, 정상화월]` |
| `HORIZON_MONTHS` | `12` | 타겟 관측창 |
| `CENSOR_END` | `'202605'` | 우측절단 기준 |

`EXCLUDE_DEFAULT_MONTH` 를 `False` 로 두면 구간이 `(부도월, 정상화월]` 로 바뀌어
부도월 1행이 남는다. **현행 산출물은 `True` 로 생성되었고, 이 값이 9,814 를 만든다.**
9,985 를 만드는 별도 설정 조합은 없다 — 9,985 는 설정 차이가 아니라 **단계 차이**다.

### 정본 = 9,814 행 (1.0350%) / 988 사

D8 실학습에 쓰인 값이라는 증거 3중:

1. `step38_production_retrain.json` 의 `scale_pos_weight = 108.6971`.
   최종 패널의 **Train core(202101~202309)** 음성/양성 = 574,573 / 5,286 = **108.69712**.
   소수 4자리까지 일치한다. (9,985 짜리 라벨이었다면 이 값이 나올 수 없다.)
2. `d8_valid_scores.parquet` = 312,334행 / `IS_BUDO_12M` 합 **3,832** —
   최종 패널의 VALID 양성과 동일.
3. 최종 패널 · 채점본 DB 의 `IS_BUDO_12M` 합이 모두 9,814.

| 구간 | 기간 | 행수 | 양성 | 음성/양성 |
|---|---|---:|---:|---:|
| Train core | 202101~202309 | 579,859 | 5,286 | 108.697 |
| Dev (early stopping) | 202310~202312 | 56,021 | 696 | 79.490 |
| Valid (홀드아웃) | 202401~202505 | 312,334 | 3,832 | 80.507 |
| **합계** | 202101~202505 | **948,214** | **9,814** | — |

`SPLIT` 컬럼 기준으로는 TRAIN 635,880행 / 5,982 양성 (= Train core + Dev), VALID 312,334행 / 3,832 양성.
