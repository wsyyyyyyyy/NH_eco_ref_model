## 개요

금융권 **신용평가 모형(Credit Scoring Model)** 개발을 위해 11개 원천 데이터 파일과 1개 도메인 마스터 파일을 모델링 가능한 클린 데이터셋으로 가공하는 전처리 파이프라인입니다.

**핵심 특징:**
- 모듈화된 클래스 구조 (`CreditDataPipeline`)
- 대용량 데이터 연산을 위한 벡터화(Vectorized) pandas 함수 사용
- 3단계 Phase별 체계적 전처리
- 파일 인코딩 자동 감지 (UTF-8 / CP949)

## 파이프라인 구조

```
nh_data_processing/
├── __init__.py         # 패키지 초기화
├── pipeline.py         # CreditDataPipeline 클래스 (핵심 로직)
├── run_pipeline.py     # CLI 실행 스크립트
└── output/             # 전처리 결과 CSV 12개
```

```
[Phase 1] 로드 & 기초 전처리
    │  ├─ 파이프 구분자 TXT 로드 (0번째 행 논리명 스킵)
    │  ├─ UPCHE EMPCN 컬럼 삭제
    │  ├─ AC12 컬럼명 통화별 리네임
    │  ├─ 소수점 왜곡(.0) 정형화 → JEMU, OBV
    │  ├─ 코드성 변수 zfill 패딩 → GRD_HIS, CRIF
    │  ├─ 날짜 '0'값 → NaT 변환 → BUDO, CRIF
    │  └─ CG01 V_BZNO 중복 제거
    ▼
[Phase 2] Wide → Long 구조 변환
    │  ├─ GRD_HIS: 연도별 2컬럼 멜트
    │  ├─ CG01: 연도별 단일 컬럼 멜트
    │  ├─ C302: 7세트 다중 컬럼 멜트
    │  ├─ AA17: 분기별 3컬럼 세트 멜트
    │  └─ AA10: 비정형 페어 멜트 (11슬롯)
    ▼
[Phase 3] 결측치 처리 & 파생변수
    │  ├─ CG01: NaN → -1 (Missing 카테고리)
    │  ├─ C302: NaN → 'Missing', NR/R 유지, 서열 인코딩
    │  ├─ AC12: NaN → 0, 기타통화 외화부채 파생변수
    │  └─ AA17: NaN → 0, 실적보유여부 플래그
    ▼
[저장] CSV 출력 (UTF-8 BOM)
```

## Phase 1: 데이터 로드 및 기초 전처리

### 1-1. 공통 로드 규칙

| 항목 | 처리 내용 |
|---|---|
| 구분자 | 파이프라인(`\|`) |
| 인코딩 | UTF-8 시도 → 실패 시 CP949 fallback |
| 0번째 행 | 한글 논리명 → `iloc[1:]`로 제거, 물리명을 컬럼으로 사용 |
| Unnamed 컬럼 | 트레일링 파이프로 인한 빈 컬럼 자동 제거 |
| 빈 행 | `dropna(how='all')`로 완전 공백 행 제거 |

### 1-추가. UPCHE EMPCN 컬럼 삭제

- **대상**: `01_기업정보_UPCHE_TOT`
- **처리**: `EMPCN`(종업원수) 컬럼 삭제
- **사유**: 종업원수는 `AA10_종업원수` 파일에서 시점별로 별도 관리되므로 마스터 테이블에서 제거
- **결과**: 7개 컬럼 → **6개 컬럼** (`V_BZNO`, `CONM`, `ETB_DT`, `COPR_OPNP_C`, `BZSCAL_C`, `STD_INDS_CFC`)

### 1-추가. AC12 컬럼명 통화별 리네임

- **대상**: `09_외화부채_AC12`
- **처리**: 원천의 순번 기반 컬럼명(`FC_AM1`, `LA_INSP_KRW_AM1` 등)을 통화별 의미 있는 이름으로 변경

| 원천 컬럼명 | 변경 후 | 의미 |
|---|---|---|
| `FC_AM1` | `US_FC_AM` | 미국 외화금액 |
| `LA_INSP_KRW_AM1` | `US_KRW_AM` | 미국 원화환산금액 |
| `FC_AM2` | `JP_FC_AM` | 일본 외화금액 |
| `LA_INSP_KRW_AM2` | `JP_KRW_AM` | 일본 원화환산금액 |
| `FC_AM3` | `CN_FC_AM` | 중국 외화금액 |
| `LA_INSP_KRW_AM3` | `CN_KRW_AM` | 중국 원화환산금액 |
| `FC_AM4` | `EU_FC_AM` | 유럽 외화금액 |
| `LA_INSP_KRW_AM4` | `EU_KRW_AM` | 유럽 원화환산금액 |
| `LA_INSP_KRW_AM5` | `TOTAL_KRW_AM` | 최종계 원화금액(합계) |

### 1-2. 소수점 왜곡 데이터 정형화

- **대상 파일**: `JEMU_재무데이터`, `VH_OBV_DTL_관찰세부등급`
- **현상**: 데이터 타입 왜곡으로 `.0` 접미사가 혼재 (예: `10.0`, `202112.0`)
- **처리 로직**:
  ```python
  df[col].astype(str).str.replace(r'\.0$', '', regex=True).str.zfill(width)
  ```
- **적용 컬럼**:

| 파일 | 컬럼 | 자릿수 | 예시 |
|---|---|---|---|
| JEMU | `AUD_OPI_DSC` (감사의견) | 2자리 | `10.0` → `10` |
| JEMU | `FNA_CLS_YM` (결산년도) | 6자리 | `202112.0` → `202112` |
| OBV | `BAS_YM` (기준년월) | 6자리 | `202101.0` → `202101` |

### 1-3. 코드성 변수 자릿수 패딩 (zfill)

- **대상 파일**: `GRD_HIS_당행등급이력`, `VH_CRIF_신용불량`

| 파일 | 컬럼 | 자릿수 | 예시 |
|---|---|---|---|
| GRD_HIS | `LS_NICS_GRDC_YYYY` | 2자리 | `3` → `03` |
| CRIF | `CRDBD_RSNC` (신용불량사유) | 4자리 | `101` → `0101` |
| CRIF | `MAX(CRDBD_RLS_RSNC)` (해제사유) | 2자리 | `1` → `01` |

### 1-4. 날짜 '0'값 예외 처리

- **대상 파일**: `BUDO_CUST_당행부도정보`, `VH_CRIF_신용불량`
- **현상**: 정상화/해제되지 않은 건은 날짜 필드에 `'0'` 또는 `'0.0'`이 입력됨
- **처리**: `'0'`/`'0.0'` → `np.nan` 치환 후 `pd.to_datetime(errors='coerce')` → `NaT`

| 파일 | 컬럼 | 의미 |
|---|---|---|
| BUDO | `NMLZ_DT` | 정상화일자 |
| CRIF | `MAX(CRDBD_RLS_OCU_DT)` | 해제일자 |

### 1-5. 시스템 오류 중복 제거

- **대상**: `CG01_나이스신용평점`
- **처리**: `V_BZNO` 기준 `drop_duplicates(keep='first')`
- **결과**: 30,903행 → **30,902행** (1건 중복 제거)

## Phase 2: Wide → Long 구조 변환

### 2-1. 당행등급이력 (GRD_HIS) — 연도별 2컬럼 멜트

- **원천 구조** (Wide): `V_BZNO | CRDEVL_PTTP_DSC_2021 | LS_NICS_GRDC_2021 | ... | _2025`
- **처리**: 연도별 `[모형구분, NICS등급]` 컬럼 쌍을 세로로 변환
- **최종 스키마**: `[V_BZNO, BASE_YEAR, CRDEVL_PTTP_DSC, LS_NICS_GRDC]`
- **결과**: 31,918행 → **108,699행** (5개년 × 사업자)

### 2-2. 나이스신용평점 (CG01) — 연도별 단일 컬럼 멜트

- **원천 구조** (Wide): `V_BZNO | KIS_LS_FNA_MKS_2021 | ... | _2025`
- **처리**: `pd.melt` → 연도 추출 → `BASE_YEAR` 생성
- **최종 스키마**: `[V_BZNO, BASE_YEAR, KIS_LS_FNA_MKS]`
- **결과**: 30,902행 → **154,510행** (5개년)

### 2-3. 나이스CRI등급 (C302) — 7세트 다중 컬럼 멜트

- **원천 구조** (Wide): `V_BZNO | 1_ST_DT | 1_ED_DT | 1_CRI_GRDNM | 2_ST_DT | ... | 7_CRI_GRDNM`
- **처리**: 1~7번 세트를 루프하며 `[시작일, 종료일, CRI등급]` 세트별 추출 → concat
- **결측 행**: 세트 내 3개 컬럼 모두 NaN인 행 제외
- **최종 스키마**: `[V_BZNO, ST_DT, ED_DT, CRI_GRD]`
- **결과**: 31,542행 → **179,167행** (최대 7세트)

### 2-4. 생산판매 (AA17) — 분기별 3컬럼 세트 멜트

- **원천 구조** (Wide): `V_BZNO | LA_XPO_AM_2021_1 | DME_AM_2021_1 | TOT_SEL_AM_2021_1 | ...`
- **처리**: `2021Q1`~`2025Q4` 분기별 `[수출, 내수, 총판매]` 3개 컬럼을 세트로 묶어 세로 변환
- **분기 식별자**: `BAS_QQ` (예: `2021Q1`, `2023Q4`)
- **결측 행**: 3개 컬럼 모두 NaN인 분기 제외
- **최종 스키마**: `[V_BZNO, BAS_QQ, LA_XPO_AM, DME_AM, TOT_SEL_AM]`
- **결과**: 4,919행 → **29,713행** (최대 20분기)

### 2-5. 종업원수 (AA10) — 비정형 페어 멜트

- **원천 구조** (Wide): `V_BZNO | BASDT1 | PERS1 | BASDT2 | PERS2 | ... | BASDT11 | PERS11`
- **처리**: 11개 슬롯의 `[일자, 인원]` 페어를 추출, 둘 다 존재하는 건만 유지
- **일자 변환**: `pd.to_datetime(format='%Y%m%d')`
- **최종 스키마**: `[V_BZNO, BAS_DT, PERS_CNT]`
- **결과**: 4,693행 → **22,763행** (최대 11슬롯)

## Phase 3: 결측치 처리 및 파생변수 생성

### 3-1. 나이스신용평점 (CG01) — Missing 카테고리

- **처리**: `KIS_LS_FNA_MKS` 수치형 결측 → **`-1`** (정수형 Missing 구간)
- **사유**: 결측치 자체가 정보를 담고 있으므로 (외부 평점 미보유), 독립 구간으로 유지

### 3-2. 나이스CRI등급 (C302) — Missing 카테고리 + 서열 인코딩

- **결측 처리**: `CRI_GRD`의 `NaN` → 문자열 **`'Missing'`**
- **특이값 유지**: `NR`(Not Rated), `R`(Review) → 그대로 보존 (별도 서열 할당)
- **파생 컬럼**: `CRI_GRD_ORD` (서열화 인코딩, Ordinal Encoding)

| 등급 | 서열 | 등급 | 서열 |
|---|---|---|---|
| AAA | 1 | BB+ | 11 |
| AA+ | 2 | BB0 | 12 |
| AA0 | 3 | BB- | 13 |
| AA- | 4 | B+ | 14 |
| A+ | 5 | B0 | 15 |
| A0 | 6 | B- | 16 |
| A- | 7 | CCC+ | 17 |
| BBB+ | 8 | CCC0 | 18 |
| BBB0 | 9 | CCC- | 19 |
| BBB- | 10 | CC+ | 20 |
| — | — | C+ | 21 |
| — | — | D | 22 |
| NR | -2 | R | -3 |
| Missing | -1 | — | — |

### 3-3. 외화부채 (AC12) — Zero-fill + 기타통화 파생변수

- **결측 처리**: 개별 국가 외화/원화 컬럼의 `NaN` → **`0`** (무역 실적 없음)
- **파생변수**: `EXT_OTHER_KRW_AM` (기타통화 외화부채 원화금액)
  ```
  EXT_OTHER_KRW_AM = TOTAL_KRW_AM - (US_KRW_AM + JP_KRW_AM + CN_KRW_AM + EU_KRW_AM)
  ```
  - 음수 발생 시 `0`으로 보정 (`clip(lower=0)`)
- **최종 컬럼**: `V_BZNO, BAS_YM, US_FC_AM, US_KRW_AM, JP_FC_AM, JP_KRW_AM, CN_FC_AM, CN_KRW_AM, EU_FC_AM, EU_KRW_AM, TOTAL_KRW_AM, EXT_OTHER_KRW_AM`

### 3-4. 생산판매 (AA17) — Zero-fill + 실적보유 플래그

- **결측 처리**: 금액형 변수 (`LA_XPO_AM`, `DME_AM`, `TOT_SEL_AM`) NaN → **`0`**
- **파생 플래그**: `EXT_PROD_RECORD_YN`
  - `1`: 원천에 데이터가 존재했던 행 (실적 보유)
  - `0`: 원천이 결측이어서 0으로 채워진 행 (실적 미보유)
- **사유**: 금액이 실제 0인 것과 데이터 자체가 없는 것을 모형이 구분할 수 있도록 함
