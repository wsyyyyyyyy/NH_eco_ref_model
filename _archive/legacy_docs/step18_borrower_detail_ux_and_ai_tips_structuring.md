## 2. 차주 상세 페이지 레이아웃 개편

- 1행(기업 개요 + AI 조기경보 의견): 2열 나란히 배치 → 1열 세로 스택
- 2행: "주요 재무/비재무"를 실제 DB 컬럼(`JEMU_121000`=자본총계, `JEMU_115000`=총자산, `JEMU_125000`=매출액, `JEMU_126000`=영업이익 — `eda_pipeline/step4_borrower_sheet.py`의 `JEMU_COL_MAP`에서 확인)로 교체하고, 기업역량진단(Radar)을 이 줄로 이동
- 3행: 부도확률 시계열 추이를 이 줄로 이동, "핵심 리스크 및 대응 방안" → "**AI** 핵심 리스크 및 대응 방안"으로 제목 변경
- 4행: 변경 없음

### 2.1 재무 이력 엔드포인트의 연도 라벨링 버그 (2차례 수정)
신규 엔드포인트 `GET /api/borrowers/{bzno}/financials`에서 두 가지 버그가 실사용 중 발견됨:

1. **라벨이 조회 시점에 종속**: 최초 구현은 "쿼리 범위 내 가장 최근 행"의 날짜를 그 재무 벡터의 연도로 사용해서, 동일한 FY2023 실적이 조회 월에 따라 "2024년"·"2025년" 등으로 제각각 표시됨. → 각 벡터가 **처음 나타난 시점**(`MIN(BASE_YM)`)의 연도로 고정.
2. **동일 연도 중복 표시**: 일부 차주는 연초 미제출 상태(0)에서 연중 실제 재무제표가 처음 등록되는 경우가 있어, 한 해에 벡터가 2개 생겨 "2021년" 컬럼이 2번 나오는 문제 발생. → 같은 연도 내 여러 벡터가 있으면 **그 해에 가장 늦게 시작된(최신) 벡터만** 채택. 200개 차주 표본 재검증 결과 중복 연도 0건.

### 2.2 상세 페이지가 헤더의 기준일 변경에 반응하지 않던 문제
`App.tsx`의 라우트가 다른 페이지(`GlobalDashboard`, `BranchDashboard`)와 달리 `BorrowerDetail`에는 전역 `baseDate` 상태를 prop으로 전달하지 않아, 리스트에서 클릭할 때의 URL 스냅샷(`?base_ym=`)에만 고정되고 이후 헤더에서 날짜를 바꿔도 반응하지 않았음. `baseYm={baseDate}`를 라우트에 추가하고, 컴포넌트가 URL 파라미터보다 이 값을 우선하도록 수정.

## 3. AI 핵심 리스크 카드 — 구조화 출력 및 아코디언 UI

- **백엔드** (`ai.py`): Gemini 호출 시 자유 텍스트 대신 `response_schema`로 `{summary: str, tips: [{title, reason}]}` 구조의 JSON을 직접 요청하도록 변경 (`google-genai`의 구조화 출력 기능 사용). 마크다운을 정규식으로 파싱하는 방식보다 안정적.
- **프론트엔드**: 3개 팁을 번호 배지가 있는 박스로 표시하고, 클릭 시 아코디언처럼 펼쳐지며 이유(reason)가 나타나도록 구현. 호버 툴팁 대신 클릭 방식을 선택 — 마우스 이동 시 사라지지 않고, 여러 직원이 각자 필요한 항목만 펼쳐볼 수 있어 업무용 대시보드에 더 적합하다고 판단.
- **검증 한계**: 세션 중 누적 테스트로 Gemini 무료 티어 일일 할당량(20회/일)이 소진되어, 실제 API 응답으로는 최종 확인하지 못함. Playwright 네트워크 인터셉트로 동일 스키마의 모의 응답을 주입하여 UI 동작(박스 표시, 클릭 펼침/접힘)만 검증 완료.

## 4. 후속 과제

- Gemini 할당량 리셋 후 실제 API 응답으로 구조화 출력이 스키마대로 오는지 최종 확인 필요.
