# 02. 전처리 설계

> **이 문서는 무엇을 다루는가**
>
> 원천 데이터를 (기업 × 월) 패널로 만드는 과정에서 내린 설계 결정과 그 근거를 다룬다.
> 핵심은 **조인 단위**다 — 원천에 월 정보가 있는데 연 단위로 붙이면 그 순간 시점
> 누수가 만들어진다. 결측 처리, 파생변수, 거시 지표의 공표 시차 배정을 함께 다룬다.
> 누수를 **발견하고 제거한** 이야기는 04 에서 다루고, 여기서는 **설계**만 서술한다.

## 목차

1. 조인 설계 — 무엇을 어떤 단위로 붙였는가
   1. as-of 조인 원칙과 공시지연(`PUB_LAG_MONTHS`)
   2. 원천별 조인 단위 표 (JEMU / AA17 / AC12 / CRIF / C302 / CG01 / OBV)
   3. 조인 단위가 시점 누수를 만드는 구조
2. 결측 처리 — 3유형 분류
   1. 유형 1 구조적 부재 → 0 + `HAS_*_YN` 플래그
   2. 유형 2 미해당 → 금액 0 / 비율 NaN
   3. 유형 3 진짜 결측 → NaN 유지 (LightGBM 네이티브 처리)
   4. `-1` 센티넬 문제와 전환
3. 파생변수
   1. JEMU 재무비율과 sentinel 디코딩
   2. 기업별 거시 노출도 5종 (`exp_*`)
   3. 업종 기반 대리변수와 하이브리드
4. 거시경제 지표 전처리
   1. 정상성 변환 — `_log_ret` / `_vol_m` / `_diff12` / `_yoy` / `_ma3m`
   2. **공표 시차 그룹 A~D** 와 실측 근거
   3. 수준·누적 계열 (Phase 6)
5. 재현성
   1. 실행 환경 통일과 패키지 버전
   2. 파이프라인 실행 순서

## 1. 조인 설계 — 무엇을 어떤 단위로 붙였는가

### 1-1. as-of 조인 원칙과 공시지연(`PUB_LAG_MONTHS`)

원칙은 하나다. **관측시점 `t` 의 행에는 `t` 시점에 실제로 조회 가능했던 값만
붙인다.** 원천 레코드에 시점 정보(`YYYYMM`)가 있으면 그 시점에 공시 지연을 더한
`AVAIL_YM` 을 계산하고, `merge_asof(backward)` 로 `AVAIL_YM ≤ t` 인 가장 최근 값을
붙인다.

재무(`JEMU`)의 공시 지연은 **`PUB_LAG_MONTHS = 4`** 다.

```
AVAIL_YM = FNA_CLS_YM + 4개월      # FNA_CLS_YM = 결산연월
```

근거는 두 가지다. (i) 12월 결산 법인의 법인세 신고기한이 3월 말이고, 재무제표가
외부에서 조회 가능해지는 것은 그 직후다. (ii) `C302`(NICE CRI 등급)의 **등급
적용시작일이 3년 연속 4월에 집중**된다 — CB 가 확정 재무를 반영해 등급을 갱신하는
시점이 4월이라는 뜻이다.[^1]

### 1-2. 원천별 조인 단위 표

| 원천 | 원천 시점 컬럼 | 실제 단위 | 조인 방식 |
|---|---|---|---|
| `JEMU` | `FNA_CLS_YM` | 결산연월 (월) | `AVAIL_YM = +4M` as-of |
| `AA17` | 분기 | 분기 누적 | 분기 공시지연 후 as-of |
| `AC12` | `BAS_YM` | 연월 (월) | **연 단위로 잘려 붙어 있었다** → 04 문서 §3-3 |
| `CRIF` | `CRDBD_OCU_YY` | **YYYYMM** | **연 단위로 잘려 붙어 있었다** → 04 문서 §3-2 |
| `C302` | `ST_DT`~`ED_DT` | 유효기간 (월) | `ST_YM ≤ t < ED_YM` 유효기간 as-of |
| `CG01` | (없음) | 연도별 wide | 연도 문자열 merge — **재구성 불가** → 04 문서 §3-1 |
| `OBV` | `BAS_YM` | 월 | 스파인이므로 직접 조인 |

★ **`AC12`·`CRIF`·`CG01` 세 원천의 조인이 시점 누수를 만들고 있었다.** 이 문서는
설계만 다루므로 여기서는 "어떻게 붙였어야 하는가" 만 적고, 실제로 어떻게 잘못
붙어 있었으며 그것을 어떻게 측정으로 증명했는지는 **04 문서**에서 다룬다.

### 1-3. 조인 단위가 시점 누수를 만드는 구조

원천에 월(`YYYYMM`)이 있는데 `str[:4]` 로 잘라 (기업, 연도) 단위로 집계·조인하면,
**그해 후반의 값이 그해 1월 행에 들어간다.** `AC12` 는 원천 레코드의 96.9% 가
12월 기준이므로 12월 값이 같은 해 1월 행에 붙어 **최대 11개월 선행**이다.

판정식은 04 문서 §2 에 있다 — "(기업, 연도) 내 월별 변동이 0 이면 연 단위 조인"
이고, 이 한 문장으로 전 피처를 전수 감사했다.

재무 as-of 의 검증은 **값이 바뀌는 달의 분포**로 한다. `PUB_LAG_MONTHS=4` 라면
값이 4월 부근에서 바뀌어야 한다.

| 변경월 | 04 | 10 | 07 | 01 | 나머지 |
|---|---:|---:|---:|---:|---:|
| `JEMU_115000`(자산총계) 변경 건수 | **70,172 (97.41%)** | 648 | 365 | 199 | 각 0.15% 미만 |

**97.41% 가 4월**이다 (`step31 --changemonth`). 이전 세대는 결산연월을 그대로
`BASE_YM` 에 맞춰 (V_BZNO, 연도) 로 조인하고 미래를 마스킹해서, 12개월 중 11개월이
결측이 되고 12월 행에 그해 12월 결산이 붙었다 — FY2021 재무가 2021-12 에 붙어
4개월 미래를 참조하는 구조였다.[^2]

## 2. 결측 처리 — 3유형 분류

결측을 한 값으로 일괄 대체하면 성격이 다른 세 상황이 뭉개진다.

### 2-1. 유형 1 구조적 부재 → 0 + `HAS_*_YN` 플래그

해당 원천 레코드가 **애초에 없는** 경우다 — 외화부채가 없는 기업의 `AC12`, 신용불량
이력이 없는 기업의 `CRIF`. 금액은 0 으로 두되 `HAS_AC12_YN` 같은 플래그를 함께
둔다. 그래야 모델이 "금액 0 = 부채 없음" 과 "레코드 없음" 을 구분할 수 있다.

### 2-2. 유형 2 미해당 → 금액 0 / 비율 NaN

계산이 정의되지 않는 경우다. 분모가 0 인 재무비율, 분기 실적이 없는 warm-up 구간
등. 금액은 0, 비율은 NaN 으로 둔다.

### 2-3. 유형 3 진짜 결측 → NaN 유지

값이 있어야 하는데 없는 경우다. **대체하지 않고 NaN 을 유지**해 LightGBM 이
네이티브 분기(결측을 별도 방향으로 보냄)로 처리하게 한다.

이전 세대는 전 컬럼 `ffill` 후 금액 컬럼을 일괄 `fillna(0)` 해서, 2021년 1~11월의
자산총계·매출액이 전부 0 이 된 행이 패널의 약 17% 였다. 세 유형을 나눈 뒤 이
문제가 사라졌다.

### 2-4. `-1` 센티넬 문제와 전환

`step1_load.py:345` 의 `fillna(-1).astype(int)` 때문에 `CG01_KIS_SCORE` 의
**140,419행(14.81%)이 실제 점수 −1** 이었다 — "평가 이력 없음" 이 점수 축의
극단값으로 들어간 것이다. 유형 3(진짜 결측)으로 재분류해 `NaN` + `CG01_MISSING_YN`
으로 바꿨다. 같은 처리를 `C302_CRI_ORD` 에도 적용했다.

이 전환의 효과 — "높은 중요도가 실제 신호인가 전처리 아티팩트인가" 의 분리 측정 —
은 04 문서 §6 에서 다룬다. `STD_INDS_CFC` 범주형의 `-1` 765건도 같은 대체값이며,
`JEMU_pl_turn_dir`(−1 = 흑자→적자) 등 **실제 값인 −1** 은 대상이 아니다.

## 3. 파생변수

### 3-1. JEMU 재무비율과 sentinel 디코딩

`JEMU` 의 증가율·비율 컬럼에는 연속값이 아니라 **센티넬 코드**가 섞여 있다. 그대로
넣으면 모델이 `10001` 을 "증가율 10001%" 로 학습한다.

| 코드 | 뜻 | 처리 |
|---|---|---|
| `10001` | 흑자 → 적자 전환 | 방향 플래그(`_dir`)로 분리, 값은 NaN |
| `10002` | 적자 지속 | 〃 |
| `10003` | 적자 → 흑자 전환 | 〃 |
| `10000` | 산출 불가 (분모 0) | **결측 아님 — 실체가 있다** (아래) |
| `±9999.99` | 상하한 캡 (실제값이 ±10000 초과) | 캡 표시 유지 |

★ **`10000` 은 결측이 아니다.** 이자보상배율(191207) `= 10000` 은 이자비용 0 =
**무차입 기업**(부도 배수 0.82, 건전 신호)이고, 재고자산회전율(191505) `= 10000`
은 재고자산 0 = **서비스·용역업**(35,291건 = 20.5%)이다. `-1` 이나 결측으로
뭉개면 무차입 우량기업과 재무 미제출 기업이 같은 값이 된다.

원본 비율을 원계정으로 **재계산**해 대체할 수 있는지 전수 그리드 서치(분자 17 ×
분모 26)로 확인했다. 판정 기준은 `|원본 − 재계산| < 0.01` 비율이다.

- **재현 성공 4건** — `191204`(매출액영업이익율) 98.96% · `191208`(자기자본순이익율)
  97.71% · `191210`(총자본순이익율) 98.77% · `191506`(총자본회전율) 100.00%.
  재계산본(`_val`)으로 대체하고 센티넬 섞인 원본은 드롭했다.
- **재현 불가 5건** — `191207`·`191310`·`191502`·`191503`·`191505`. 이자비용·매출채권·
  영업자산·재고자산 계정이 원천에 없어 분리가 불가능하다. 원본 의존이 불가피하며,
  **드롭 후보로 올리지 않는다** — `191207_val` 은 영업적자 배수 1.50 → 무차입 0.82
  로 단조성이 뚜렷하다.

예외로 매출액증가율(191104)의 `10001~10003` 은 부호 패턴이 맞지 않아(실측 일치율
2~13%) 소스 산출 오류로 보고 결측 처리한다. `191104` 의 `10000`(전기매출 0)은
유효하다.

배선 위치는 `step2._join_jemu` 직전(jemu 프레임 단계)이다 — `consec_loss_years` /
`pl_turn_dir` 이 연속 결산 시계열을 필요로 하는데, 패널 단계에서는 as-of 조인으로
같은 결산이 여러 달에 반복 등장해 계산이 왜곡되기 때문이다.

### 3-2. 기업별 거시 노출도 5종 (`exp_*`)

거시 지표는 `BASE_YM` 하나당 값이 하나이므로 그대로 넣으면 시점 더미가 된다
(05 문서 §2-1). 그래서 거시 충격에 **기업별 노출도**를 곱해 상호작용항을 만든다.
노출도의 정의·커버리지는 05 문서 §2-3 에 표로 있고, 요약하면 다음과 같다.

| 노출도 | 정의 | 결측률 |
|---|---|---:|
| `exp_fx` | 수출비중 (`AA17` 기반) | 89.51% |
| `exp_fx_dbt` | 외화부채비중 (`AC12`/`JEMU`) — **(d) 부분오염** | 5.28% |
| `exp_rate` | 차입 의존도 (`JEMU_118000`/`JEMU_115000`) | 5.28% |
| `exp_liq` | 단기부채비중 (`JEMU_116000`/`JEMU_118000`) | 5.32% |
| `exp_inv` | 재고부담 (`JEMU_191505_val`) | 5.71% |

`exp_fx_dbt` 는 분자 `AC12_TOTAL_KRW_AM` 이 연 단위 조인분이라 시점 부분오염을
포함한다 — 판정 근거와 해소 경로는 04 문서 §2-3 · §3-3, 미적용 사유는 07 문서
§2-1 에 있다.

### 3-3. 업종 기반 대리변수와 하이브리드

`exp_fx` 는 결측률이 89.51% 라 그대로 쓰기 어렵다. `AA17` 미보고 기업에는 **업종
대분류 평균**을 대리값으로 채운 `exp_fx_hybrid`(결측 11.04%)를 만들었다. 다만
최종 구성(D8)에서는 `exp_fx` 계열 상호작용항이 결측률 때문에 탈락했다(05 문서 §8-4).

업종 자체는 **대분류(`STD_INDS_SECTION`)만** 쓴다. 중분류(`STD_INDS_MID2`, 71값)는
업종당 평균 74건이라 트리가 개별 업종의 부도율을 외우는 과적합이 나타나 제거했다
(C축, 03 문서 §3-2 · 04 문서 §5-3).

## 4. 거시경제 지표 전처리

### 4-1. 정상성 변환

부도율 추세와 겹친다(05 문서 §5, `CPI_core` 사례). 정상성 변환을 적용해 변환 변수
**178개**를 만든다.

| 접미사 | 대상 | 개수 |

| 소계 | | **89** |

> 금리 지표에 YoY 를 쓰지 않는다 — 제로 금리 국면에서 분모가 발산한다.
> 원천 레벨 컬럼은 최종 출력에서 전부 삭제된다.
> `AA17` 은 연내 누적치라 차분해서 쓴다 (연내 단조 증가 96.6%, Q4 = 연매출 일치,
> 천원 단위).

> 이미 178개였으므로 매핑 정정이 개수를 바꾼 것이 아니다

### 4-2. 공표 시차 그룹 A~D 와 실측 근거

거시 지표는 `impute_data` Phase 1 에서 그룹별 시차가 적용된다. `step6` 에서 또
시차를 걸면 이중 적용이므로, 게이트 1 이 **패널에서 관찰되는 실제 총 시차**를 재서
기대값과 대조한다.

| 그룹 | 시차 | 지표 수 | 성격 |
|---|---:|---:|---|
| A | +0 | 35 | 시장 종가 — 당월 즉시 관찰 가능 (금리·환율·주가) |
| B | +1 | 10 | 월간 통계 (CPI·PPI·수출입지수) |
| C | +2 | 17 | 통화량·국제수지·심리·KOSIS 3종 |
| **D** | **+3** | **3** | `household_credit` · `household_loan` · `current_account_quarterly` |

**Group D 를 신설한 근거는 관측된 공표 지연 하나다.** 분기 지표라는 사실 자체는
시점 누수 사유가 아니다 — 분기 지표는 (기업,연도) 안에서 4회 변하고 `ffill` 은
과거 값을 반복하므로 `GNI_annual` 처럼 "연도 내 변동 0" 이 되는 구조와 다르다.
시차를 정한 근거는 **ECOS 실데이터의 최종 수록월을 직접 관측**한 것이다 — 세 지표
모두 측정일(2026-09-01) 기준 최종 수록월이 3개월 전이었다. Group C(+2) 에 두면
1개월 look-ahead 가 남는다.

★ **이 근거는 하루치(월초) 관측이다.** 월초 측정은 직전월 공표를 아직 못 봤을 수
있어, 경계선에 걸린 월간 계열 15건은 **시차를 바꾸지 않고 월 중순 재관측 대기**로
남겼다 (`PENDING_REVALIDATION.md` 11번). 분기 3건의 경과 3개월은 월초 효과로
설명되지 않아 이동을 확정했다.

보정 후 전수 재검사 **걸림 0건** (65개 지표).

### 4-3. 수준·누적 계열 (Phase 6)

일부 지표는 변화율이 아니라 **수준·누적** 형태가 경제적으로 의미 있다 — 신용스프레드
