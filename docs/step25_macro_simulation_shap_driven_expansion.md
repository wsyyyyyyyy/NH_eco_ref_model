# [Step 25] 매크로 시뮬레이션 버그 수정 및 SHAP 기반 슬라이더 확장

> **작성일**: 2026-07-04
> **기준**: 사용자가 시뮬레이션 히트맵 색상이 반대로 보인다고 지적, SHAP 상위 50개 요인 중 외부 API 지표가 시뮬레이터에 반영되어야 한다고 요청

---

## 1. 배경

사용자가 실제로 자신이 뽑아본 SHAP 분석(EUR_KRW_vol_m, BSI_mfg_export_yoy_ma3m, KORIBOR_12m_diff12, soybean_log_ret_ma3m 등)을 근거로 "이런 외부 API 지표들이 상위 50개 영향 요인에 들어가는데 매크로 시뮬레이션 화면에 반영해야 한다"고 요청. 또한 기준금리+100bp·환율+70원을 적용한 히트맵이 전부 초록색(위험 감소)으로 나오는 게 이상하다고 지적("색이 반대인 것 같아").

## 2. 진단

`POST /api/simulation/`을 직접 호출해 재현 후, 금리/환율을 각각 단독으로 넣어 원인을 분리:

- **환율만 +70원**: 8개 업종 전부 diff = **정확히 0.00** (전혀 영향 없음)
- **금리만 +100bp**: 전체 결과와 동일 — 사실상 금리 하나가 결과를 좌우

### 버그 A: 금리 단위 변환 누락
`apply_macro_shock`가 UI의 "bp" 슬라이더 값을 그대로 %p 단위 컬럼(`_RATE_COLS`)에 더하고 있었음. `base_rate_diff12` 실측값은 -0.23(%p) 수준인데 "+100bp"를 그대로 더하면 99.77%p라는 현실에 존재할 수 없는 충격이 가해짐. LightGBM native importance로 확인한 결과 `call_rate_overnight_diff12`는 gain=63.6(전체 중 미미)인데도, 100배 부풀려진 입력값이 모델을 완전히 분포 밖(out-of-distribution)으로 밀어내 결과가 왜곡됨.

### 버그 B: 환율 슬라이더가 진짜 중요한 변수를 놓침
`USD_KRW_log_ret`는 LightGBM에서 스플릿 2회만 쓰인 사실상 무의미한 변수(gain=63.6)인데 환율 슬라이더는 이것만 움직임. 반면 전역 SHAP 중요도(`mean(|shap|)`, 26,184개사 전체 기준)를 계산한 결과 **`EUR_KRW_vol_m`이 거시변수 중 2위**(gain=210,801, split_count=71, KOSPI_log_ret 다음)인데 어떤 슬라이더도 이 컬럼을 건드리지 않고 있었음.

### 전역 SHAP 상위 50개 (외부 API 거시지표만, 회사 고유 재무정보 제외) 중 슬라이더 미연동 상위 항목
1위 KOSPI_log_ret, 2위 EUR_KRW_vol_m, 5위 household_loan_yoy_ma3m, 6위 BSI_mfg_export_yoy_ma3m, 10~13위 천연가스·옥수수·미국채2년물·대두, 14위 KOSPI_vol_m, 19~20위 상해종합지수·JPY_KRW_vol_m 등 다수.

## 3. 조치

### 백엔드 (`backend/model_inference.py`, `backend/routers/simulation.py`)
- `interest_rate`를 `/100`으로 나눠 bp→%p로 정확히 변환 후 `_RATE_COLS`에 적용.
- 환율 충격에 `EUR_KRW_vol_m`(+`EUR_KRW_log_ret`, `JPY_KRW_vol_m`)도 함께 연동.
- **신규 슬라이더 3종 추가** (전역 SHAP 상위 항목 반영):
  - `kospi_shock` (국내 증시, %): `KOSPI_log_ret`, `KOSPI_vol_m`, `KOSDAQ_vol_m_ma3m`
  - `global_risk_shock` (글로벌 리스크, VIX pt): `VIX_vol_m`, `DowJones_log_ret`, `NASDAQ_vol_m`, `Shanghai_Composite_log_ret_ma3m`
  - `commodity_shock` (원자재 확장, %): 기존 유가 슬라이더에 더해 금·옥수수·대두·천연가스·구리·은

### 프론트엔드 (`frontend/src/pages/MacroSimulation.tsx`, `mockup.html`)
- 좌측 패널에 슬라이더 3개 추가(5개→8개), 역사적 위기 프리셋(IMF/2008/스태그플레이션/연착륙) 값도 신규 파라미터에 맞게 갱신 (예: IMF 위기는 코스피 -50%, VIX +30pt).
- `mockup.html`도 동일하게 8개 슬라이더 + 프리셋 반영.

## 4. 검증

| 시나리오 | 수정 전 | 수정 후 |
|---|---|---|
| 환율만 +70원 | 전 업종 diff = 0.00 | 실질적인 diff 발생 (-0.75 ~ -3.31%p) |
| 코스피 -15% 단독 | (슬라이더 자체가 없었음) | 전 업종 diff **양수**(+0.8~+1.8%p, 직관과 일치: 증시 폭락 → 위험 증가) |
| IMF 위기 프리셋 적용 | 위험 **감소**로 표시(직관과 반대) | 전 업종 위험 **증가**로 표시(빨간 막대가 회색 초과) |

`npx tsc --noEmit` 통과, Playwright로 실제 화면과 `mockup.html` 양쪽에서 8개 슬라이더 렌더링 및 IMF 프리셋 적용 확인, 콘솔 에러 0건.

## 5. 유로 전용 슬라이더 추가 (사용자 후속 요청)

"유로 영향이 큰데 유로도 하나 넣어달라"는 요청에 따라, 처음엔 환율(원/달러) 슬라이더에 `EUR_KRW_vol_m`을 묶어서 반영했던 것을 분리해 **독립된 "유로 환율(원/유로)" 슬라이더**를 신규 추가(9번째 슬라이더). `apply_macro_shock`에 `eur_shock` 파라미터를 추가해 `EUR_KRW_log_ret`, `EUR_KRW_log_ret_ma3m`, `EUR_KRW_vol_m`을 원/달러와 독립적으로 조작 가능. 역사적 위기 프리셋에도 유로 값 반영(IMF 위기 +60원, 2008 금융위기 +45원 등). 유로 단독 +50원 테스트로 실질적 diff(-0.69~-3.17%p) 발생 확인.

## 6. 남은 이슈 (버그 아님, 확인 후 보류)

VIX(+25pt)·원자재(+20%) 단독 충격은 여전히 위험이 **감소**하는 방향으로 나옴(코스피처럼 직관과 일치하지 않음). 두 버그(단위 변환, 미연동 변수)를 모두 수정한 뒤에도 남아있는 현상이라 코드 버그가 아니라 **모델이 학습 데이터에서 실제로 그렇게 학습한 패턴**으로 판단 — 이전 세션에서 이미 "복합 거시 충격이 예측 위험을 낮추기도 함"을 개별 변수 단위 테스트로 검증하고 "실제 모델 동작, 파이프라인 버그 아님"으로 문서화한 것과 같은 종류의 현상. 강제로 부호를 뒤집지 않고 현상 그대로 유지.
